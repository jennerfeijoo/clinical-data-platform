# Independent reproducible Synthea cohorts

## Purpose

This workflow creates two independent synthetic populations under one controlled study design. It is designed to demonstrate repeatable source generation, artifact identity, identifier separation, and multi-cohort loading through the existing governed pipeline.

It does not establish epidemiological representativeness, clinical validity, prevalence estimates, or suitability for identifiable patient data.

## Packaged profiles

| Control | Cohort A | Cohort B |
|---|---|---|
| Profile | `synthea-us-small-v1` | `synthea-us-small-cohort-b-v1` |
| Synthea release | `v4.0.0` | `v4.0.0` |
| Population | 100 | 100 |
| Random seed | `20260729` | `20260829` |
| Clinician seed | `20260730` | `20260830` |
| Reference date | `2026-07-29` | `2026-07-29` |
| Geography | Massachusetts | Massachusetts |
| Threads | 1 | 1 |
| Retained history | Complete | Complete |

The design variables are intentionally equal. Only the random and clinician seeds differ. This makes cohort B an independent stochastic replica rather than a simultaneously changed geography, population size, software release, or observation window.

The profiles are packaged at:

```text
src/clinical_data_platform/synthea_profiles/
├── reproducible_small.toml
└── reproducible_small_cohort_b.toml
```

## Why two seeds change

Synthea separates the population random seed from the clinician seed. Reusing either seed would leave part of the generated environment shared across cohorts. The cohort comparison therefore requires both seed values to differ.

## Verification sequence

Each cohort independently passes:

```text
packaged profile
→ pinned Synthea checkout
→ exact generation command
→ six source CSV fingerprints
→ source dataset fingerprint
→ deterministic adapter
→ six contract-ready CSV files
→ terminology CSV
→ adaptation fingerprint
→ executable-contract verification
```

The pair then passes:

```text
same controlled design
AND distinct profile hashes
AND distinct random seeds
AND distinct clinician seeds
AND distinct adaptation fingerprints
AND zero identifier overlap in all six entities
```

## Identifier domains

The comparison reads and fingerprints the primary identifier domain for every clinical entity:

| Dataset | Identifier |
|---|---|
| patients | `patient_id` |
| encounters | `encounter_id` |
| diagnoses | `diagnosis_id` |
| observations | `observation_id` |
| medications | `medication_id` |
| procedures | `procedure_id` |

Every identifier must be non-empty and unique within its cohort. The intersection between cohorts must be empty for every dataset. This prevents an independent population from being interpreted as updates to a previously loaded patient or event.

## Comparison fingerprint

The stable comparison fingerprint covers:

```text
comparison schema version
controlled study design
profile names and profile SHA-256 hashes
random and clinician seeds
adaptation fingerprints
adapted row counts
omission counts
terminology counts
identifier counts
identifier-set fingerprints
zero-overlap counts
```

It excludes:

```text
creation timestamp
absolute filesystem paths
PostgreSQL run UUIDs
```

Consequently, repeated comparison of unchanged cohort artifacts produces the same comparison fingerprint even when executed at another time or in another directory.

## Evidence artifacts

The comparison writes:

```text
data/synthea/cohort-comparison/
├── synthea-cohort-comparison.json
└── synthea-cohort-comparison.md
```

The JSON file is machine-readable evidence. The Markdown file is a review summary containing profiles, seeds, adaptation fingerprints, row counts, and overlap results.

When both cohorts are loaded, the workflow also writes:

```text
synthea-cohort-load.json
```

This execution artifact maps the stable cohort comparison to the twelve PostgreSQL pipeline run identifiers generated by the two six-dataset loads.

The load execution fingerprint is intentionally distinct from the reproducibility fingerprint because PostgreSQL run UUIDs identify a particular execution.

## Manual commands

List packaged profiles:

```powershell
clinical-data-cohort list-profiles
```

Inspect cohort B:

```powershell
clinical-data-cohort profile synthea-us-small-cohort-b-v1
```

Generate cohort B:

```powershell
clinical-data-cohort generate synthea-us-small-cohort-b-v1 `
  --workspace data/synthea/synthea-us-small-cohort-b-v1
```

Adapt cohort B:

```powershell
clinical-data-cohort adapt synthea-us-small-cohort-b-v1 `
  data/synthea/synthea-us-small-cohort-b-v1/generated/csv `
  --output-dir data/synthea/synthea-us-small-cohort-b-v1/normalized `
  --generation-manifest `
    data/synthea/synthea-us-small-cohort-b-v1/synthea-generation-manifest.json
```

Verify cohort B:

```powershell
clinical-data-cohort verify synthea-us-small-cohort-b-v1 `
  data/synthea/synthea-us-small-cohort-b-v1/normalized
```

Compare the pair:

```powershell
clinical-data-cohort compare `
  data/synthea/synthea-us-small-v1/normalized `
  data/synthea/synthea-us-small-cohort-b-v1/normalized `
  --output-dir data/synthea/cohort-comparison
```

## Pair loading

Use a migrated database that does not already contain identifiers from either cohort:

```powershell
.\scripts\load_synthea_cohorts.ps1 -ReplaceComparison
```

Direct command:

```powershell
clinical-data-cohort load-pair `
  data/synthea/synthea-us-small-v1/normalized `
  data/synthea/synthea-us-small-cohort-b-v1/normalized `
  --processed-root data/processed/synthea-cohorts `
  --raw-root data/raw `
  --output-dir data/synthea/cohort-comparison `
  --replace
```

The loader performs a database preflight across all six identifier domains before loading cohort A. If any identifier from either cohort already exists, it refuses the operation before creating new validation or persistence runs.

The two cohorts use separate processed roots:

```text
data/processed/synthea-cohorts/
├── cohort_a/
│   ├── patients/
│   ├── encounters/
│   ├── diagnoses/
│   ├── observations/
│   ├── medications/
│   └── procedures/
└── cohort_b/
    ├── patients/
    ├── encounters/
    ├── diagnoses/
    ├── observations/
    ├── medications/
    └── procedures/
```

Raw objects remain content-addressed, while every dataset reception receives its own append-only raw receipt. PostgreSQL stores one completed pipeline run per dataset and cohort, resulting in twelve run identifiers for a complete pair load.

## Transaction boundary

The six datasets within a cohort and the two cohorts are not committed as one global database transaction. Each dataset follows the existing durable lifecycle and transaction boundaries. If a later dataset fails, earlier completed runs remain auditable.

The pair load manifest is written only after both cohorts complete successfully.

## CI evidence

Normal CI uses two small, disjoint, checked-in Synthea-shaped fixtures. It verifies:

- both packaged profiles and their controlled differences;
- deterministic comparison fingerprints;
- zero overlap across all six identifier domains;
- rejection of overlapping cohorts;
- sequential loading through raw capture, contracts, COPY staging, terminology, history, constraints, and durable audit;
- twelve distinct completed pipeline runs;
- refusal to load the same pair again into a database containing its identifiers.

The full Java generator remains outside normal CI because it requires cloning Synthea and executing a larger JVM workflow.

## Interpretation boundary

The second cohort demonstrates that the engineering system can distinguish and process two independently seeded synthetic populations. Differences between their counts or clinical concepts are stochastic outputs of Synthea under the configured design.

They must not be interpreted as measured differences between real populations, hospitals, regions, treatment groups, or time periods.
